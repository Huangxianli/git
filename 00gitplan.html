01

阶段一：单兵作战与版本控制基础

⏱️ 建议时间：Day 1 ~ Day 3（奠基阶段）
核心基石
🎯 阶段学习目标：深刻理解“工作区、暂存区、版本库”的三层架构，掌握单人开发下的提交、比对、撤销等核心循环。
环境配置与初始化仓库 git config git init
配置全局用户名与邮箱（关联以后的 GitHub 提交记录）；在本地文件夹初始化 .git 目录。
git config --global user.name "你的名字" git config --global user.email "you@example.com" git init
暂存区与提交闭环 git status git add git commit
查看当前文件状态（Untracked / Modified），将修改提交到暂存区，并附带清晰语义的 commit 消息。
git status git add . git commit -m "feat: 首次初始化基础结构与页面"
历史回溯与文件差异比对 git log git diff
查看简洁美观的提交树图；比对工作区和暂存区之间的代码具体改动行。
git log --oneline --graph --all git diff
常见撤销与后悔药命令 git restore git rm --cached
丢弃工作区的未保存改动；或将错误 git add 到暂存区的文件移出（但保留本地文件）。
git restore <文件名> # 丢弃工作区改动 git rm --cached <文件名> # 从暂存区移出，取消跟踪
02

阶段二：分支艺术与冲突管理

⏱️ 建议时间：Day 4 ~ Day 7（进阶分水岭）
高频必考
🎯 阶段学习目标：搞懂分支指针的本质，学会在隔离环境下开发功能（Feature Branch），并熟练处理 Merge 冲突与临时存储。
现代分支创建与切换语法 git switch git branch
掌握官方推荐的 git switch（替代过去语义混乱的 checkout），创建并快速切换特性分支。
git switch -c feature/login # 创建并切换到新分支 git branch -a # 列出所有本地及远程分支
分支合并与差异：Fast-Forward 与三方合并 git merge
理解快进合并（Fast-Forward）与 --no-ff 创建独立 merge 节点的不同使用场景。
git switch main git merge --no-ff feature/login -m "merge: 合并登录模块到主分支"
代码冲突（Conflict）实战解决 <<<<<<< HEAD =======
模拟两人修改同一行代码产生的冲突标记，手动保留合适代码，再执行 add & commit 完成解决。
工作现场临时封存与恢复 git stash
当做到一半有紧急 Bug 需要切主分支修时，用暂存袋将当前半成品代码先打包存起来。
git stash save "正在开发的半成品组件" git stash pop # 恢复并弹出最新的一份暂存
03

阶段三：远程协同与团队工作流（GitHub / Gitee）

⏱️ 建议时间：Day 8 ~ Day 11（实战协作）
团队必备
🎯 阶段学习目标：联通云端，熟练使用 SSH Key 免密认证、Pull Request (PR) 流程以及主流团队工作流（GitHub Flow / Git Flow）。
SSH 秘钥配置与关联远程仓库 ssh-keygen git remote
生成 ed25519 或 rsa 密钥并添加到 GitHub Settings；使用 git remote add origin 连接仓库。
ssh-keygen -t ed25519 -C "you@example.com" git remote add origin git@github.com:username/repo.git git push -u origin main
日常推送与拉取：Fetch vs Pull 的底层差异 git fetch git pull
理解 git pull = git fetch + git merge。掌握推荐的 git pull --rebase 保持干净线性历史。
git pull --rebase origin main
Pull Request (PR) / Merge Request (MR) 完整演练 Fork PR Code Review
通过 Fork 他人项目或在团队仓库新建 feature 分支发起 PR，模拟 Code Review 评审与合并流程。
忽略规则与文件清理 .gitignore git rm
规范编写 .gitignore（过滤 node_modules、.env、IDE 配置等）；处理不小心已被提交到仓库的垃圾文件。
04

阶段四：高阶技巧与终极后悔药（资深必备）

⏱️ 建议时间：Day 12 ~ Day 15（分水岭进阶）
架构进阶
🎯 阶段学习目标：掌握交互式变基整理优雅历史、精确移植指定提交、利用底层 Reflog 救回被误删的分支与代码。
交互式变基：合并与美化提交历史 git rebase -i squash
将本地杂乱的诸如 "fix typo"、"bugfix 1" 等多个碎片提交压缩合并（Squash）成一个高质量提交后再推远端。
git rebase -i HEAD~3
精准摘取单次提交 git cherry-pick
跨分支单点提取某个修复 Bug 或特性的 commit hash，并无缝重放到当前分支上。
git cherry-pick
绝境重生的“全黑盒飞行记录仪” git reflog
即使执行了 git reset --hard 或者误删了本地分支，也能在 reflog 里找到悬空指针并一键复活。
git reflog git reset --hard HEAD@{3} # 恢复到第 3 步之前的任何操作状态
二分排查法定位 Bug 罪魁祸首 git bisect git blame
自动化二分法查找是哪一次历史 commit 引入了重大 Bug；查看某一行代码的作者和修改背景。

阶段五：工程化规范与效能工具

⏱️ 建议时间：Day 16+（工程化与终身受益）
工程标准
🎯 阶段学习目标：落地企业级 Commit 规范（Conventional Commits），配置自动化 Hooks 校验，并使用现代化效率终端工具。
Conventional Commits 规范化提交信息 feat: fix: docs: refactor:
遵循业界通用的提交前缀约定，配合 commitlint 与 husky，在 commit 时自动校验信息格式。
Git 快捷别名（Aliases）打造专属高效工作流 git config alias
给冗长的常用命令配置极简短别名，每天节约大量敲键盘时间。
git config --global alias.st status git config --global alias.co checkout git config --global alias.lg "log --color --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit"
体验现代化辅助 GUI / TUI 生产力工具 lazygit VSCode GitLens
在掌握命令行原理的基础上，拥抱 lazygit 终端看板或 VSCode GitLens 插件，让效率提升数倍。
版本发布与打 Tag 规范 git tag
配合语义化版本号（Semantic Versioning 如 v1.0.0）为生产发布打附注标签并推向远端 Releases。
git tag -a v1.0.0 -m "Release version 1.0.0" git push origin v1.0.0

创建并切换至新分支
git switch <name>

git stash
将未提交的修改保存到储藏栈

git stash list

🔍 查看与比对

比对暂存区与最后一次提交的差异
git log -n 5 --oneline
查看最近 5 条极简单行提交记录
git blame <file>
逐行显示每行代码的作者与 commit 时间
⚠️ 场景 1：刚做完一次 commit，发现写错或者少加了一个文件？
不要慌！直接把漏掉的文件 git add 暂存，然后执行追加修复命令，将不会产生多余的垃圾 commit：
git add 遗漏的文件 git commit --amend --no-edit # 合并到上一次提交且不修改提交信息
⚠️ 场景 2：工作区写乱了，想彻底放弃某个文件的修改，恢复成最后一次 commit 的样子？
使用现代 restore 命令一键复原：
git restore <文件路径> # 放弃单个文件修改 git restore . # 放弃当前目录下所有文件的未暂存修改
⚠️ 场景 3：手滑把代码全部 hard reset 回去了，或者误删了一个分支？代码找不到了！
只要你的代码曾经 commit 过，Git 就绝不会轻易丢弃它！使用飞行记录仪 reflog 找到它死前的 Hash，瞬间复活：
git reflog # 查看你最近敲过的所有动作及对应的 HEAD 索引 git reset --hard HEAD@{1} # 瞬间穿越回到执行 reset 之前的那一刻！
⚠️ 场景 4：合并分支发生冲突（Merge Conflict），发现改乱了想彻底终止本次合并？
随时可以通过 abort 参数直接取消本次合并，工作区立刻回到合并前的状态：
git merge --abort # 放弃当前处于冲突中的合并动作
⚠️ 场景 5：提交了敏感配置（如 API Key 或 .env 文件），如何从版本树中抹除？
如果还没推送到远程仓库，可以使用重置并强制重新提交；如果已经推到远程，优先推荐使用 git-filter-repo 或 BFG Repo-Cleaner 工具彻底净化提交历史。
